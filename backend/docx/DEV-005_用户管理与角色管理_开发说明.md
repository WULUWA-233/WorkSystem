## 4. 核心类说明

### 4.1 SysUserServiceImpl
- **用户分页**: LambdaQueryWrapper 动态条件 + Page 分页，自动查询每个用户的角色
- **新增用户**: 校验 username 唯一 → BCrypt 加密 → 插入用户 → 批量插入角色关联（事务）
- **删除用户**: 保护 admin / 自己 → 逻辑删除用户 → 逻辑删除角色关联（事务）
- **状态切换**: 校验 status ∈ {0,1} → 保护 admin 不被禁用 → 保护自己不被禁用
- **密码重置**: BCrypt 加密新密码 → 更新
- **角色分配**: 保护 admin 的 ADMIN 角色 → 校验角色存在/启用 → 删旧 → 插新（事务）

### 4.2 SysRoleServiceImpl
- **角色分页**: LambdaQueryWrapper 动态条件 + Page 分页
- **角色 options**: 只返回 status=1 且 deleted=0 的角色
- **删除角色**: 保护 ADMIN(1) 和 SALES(2) → 检查是否有用户绑定 → 逻辑删除
- **roleCode 自动大写**: CreateDTO setter 中 `toUpperCase()`

### 4.3 AdminInterceptor
- **拦截路径**: `/api/v1/system/users/**`, `/api/v1/system/roles/**`
- **流程**: LoginUserContext 获取 userId → SysRoleMapper 查询角色 → 检查 "ADMIN" → 无则抛 BusinessException(FORBIDDEN)
- **角色缓存**: 查询后将角色存入 LoginUserContext，后续 Controller 可通过 `isAdmin()` 判断

### 4.4 WebMvcConfig
- 注册 AdminInterceptor，限定拦截路径为系统管理接口

## 7. 用户管理业务规则

- username 唯一，新增时校验
- password BCrypt 加密存储，API 不返回 password
- 新增用户默认 status=1
- 删除使用逻辑删除（deleted=1），同时删除角色关联
- admin 账号不允许删除、不允许禁用、不允许移除 ADMIN 角色
- 不允许删除/禁用当前登录用户自己
- 修改用户不修改 username/password（密码有专门重置接口）

## 8. 角色管理业务规则

- roleCode 唯一，自动转大写
- 删除前检查是否有用户绑定该角色
- ADMIN(1) 和 SALES(2) 为内置角色，不允许删除
- 角色禁用后 role options 不返回
- 修改时不允许修改 roleCode

## 9. 权限控制说明

**实现方式**: HandlerInterceptor（AdminInterceptor）

**拦截路径**: `/api/v1/system/users/**`, `/api/v1/system/roles/**`

**流程**:
```
请求 /api/v1/system/users
  → JwtAuthenticationFilter（验证 Token，设置 userId/username）
    → AdminInterceptor.preHandle()
      1. 获取 userId → LoginUserContext.getCurrentUserId()
      2. 查询角色 → sysRoleMapper.selectByUserId(userId)
      3. 存入上下文 → LoginUserContext.setCurrentUser(userId, username, roles)
      4. 检查 ADMIN → roleCodes.contains("ADMIN")
      5. 非 ADMIN → throw BusinessException(FORBIDDEN, "无权限访问")
      6. ADMIN → 放行
```

**未登录**: JwtAuthenticationFilter 返回 401
**已登录非 ADMIN**: AdminInterceptor 返回 403
**已登录 ADMIN**: 正常访问
